# program.md：云边投机推理上行优化（近似草稿分布 + 草图门控）

> 目标：用一个小压缩量替代上传完整草稿分布 Q，通过“低秩近似 + 随机草图门控 + 可回退”实现**有损但可控**的加速，并写成 CCF A 会论文的一个优化点。
> 使用者：另一个 agent 依此实现实验代码。本文即实验规格书（spec），不是论文正文。

---

## 0. 一句话定位

在边端–云端投机推理中，**不上传完整草稿分布 Q（N×V）**；改用
（a）低秩表示只传 N×r 的系数 + 共享基增量（b）共享随机种子生成的草图 R 传 N×k 的 sketch 做门控（c）超阈值时回退到完整 Q 或 token-only 精确匹配。
近似 Q̃ **只用于接受判定**，拒绝后的重采样一律使用云端精确 P，因此**输出分布的支撑不被污染**，损失的只是接受率。

**基线对照（本期只做两条，其余移出主表）：**

| 编号 | 名称 | 上行内容 | 性质 |
|---|---|---|---|
| B0 | 云端单独解码 | 无 | 质量上界、延迟基线（必跑，作参照） |
| B1 | 标准 SD（传完整 logits） | N×V | 无损上界（接受率/质量） |
| B2 | token-only 精确匹配（Ygg 式） | N×token | 无损、低带宽下界 |
| Ours | 低秩 Q̃ + 草图门控 + 可回退 | N×k + N×r(+ΔB) | 本文方法 |

> 暂不进主表：int8 逐通道量化（降级为附录一行）、SlimSpec / FR-Spec / VocabTrim 等词表与低秩 LM-head 工作（仅 related work 一句血缘说明）、EdgeSpec / BaF / SplitLLM 等云边特征传输工作（仅 related work 一句正交说明）。若后续需要补强度，再按第 7 节“扩展对照”加回。

## 1. 符号与场景

- V：词表大小；N：草稿长度（每步草稿 token 数）；d：隐藏维度；r：低秩秩；k：草图维度。
- P(x)：云端目标分布；Q(x)：边端草稿分布；Q̃：边端上传的近似分布；R：共享种子生成的投影矩阵（稀疏 ±1 或高斯，维度 k×V）。
- 门控分数：a = ‖R·Q − R·P_est‖ 或近似 TV/KL 估计，见 §4。
- 场景：边端运行 draft 模型，云端运行 target 模型；上行链路带宽 B_up（可配置 1/5/10/50/100 Mbps），RTT 可配置（10/30/50 ms）。

## 2. 方法（实现规格）

### 2.1 低秩表示（边端）

1. 维护基 B ∈ R^{V×r}，跨步热启动（幂迭代更新，不做从头 SVD）。
2. 每步把 N 个位置的 log-Q（**不是概率**，长尾单独处理，见 §2.4）投影到 B，得到系数 c ∈ R^{N×r}。
3. 上行：c（fp16）+ B 的增量（只传变化超过阈值的列/元素）+ sketch s（见 §2.3）。
4. r 取 {2, 4, 8} 三档，作为率失真旋钮。

### 2.2 云端还原

- Q̃ = softmax(B·c)；仅用于**接受判定** min(1, P(x)/Q̃(x))。
- 被拒时从 norm(max(0, P − Q̃)) 重采样 → 必须改用 **norm(max(0, P − Q_full))**，即重采样恒用精确 P；若无完整 Q 则退化为 token-only 精确匹配（§2.5）。

### 2.3 草图门控（零训练）

1. 双方 `seed` 约定后本地生成 R（k×V，稀疏 ±1，每行非零数固定）。
2. 边端算 s = R·Q（k 维，fp16），随系数一起上行。
3. 云端算 s_P = R·P（精确 P 就在云端，零成本），得偏差分数 a（§4）。
4. a ≤ θ → 用 Q̃；a > θ → 回退（§2.5）。
5. k 取 {64, 128, 256}。

### 2.4 长尾处理（必须实现）

- top-k_t（k_t 取 16/32）高概率 token **精确传**（token id + 概率），不进低秩；
- 剩余长尾部分做低秩近似；
- 这是接受率不掉的关键实现细节， ablation 要单独验证“有/无长尾精确”的差异。

### 2.5 回退策略（两种，可切换）

- 回退-A：边端补发完整 Q（N×V），云端用完整 Q 做接受与重采样 → 无损，但多一次传输。
- 回退-B：切换到 token-only 精确匹配验证（P(x)==Q_token(x)），不补传 Q → 有损一步，但零额外字节，保证每步至少推进 1 token。
- **默认实现回退-B**，并把回退-A 作为 upper-bound 对照。

### 2.6 隐藏回退 RTT 的工程实现（关键）

- 边端**乐观地**把 sketch + 系数 + 完整 Q 在同一批次 pipeline 发出（完整 Q 可后置、与草图判断重叠）。
- 云端先用 sketch 判断；OK 则丢弃完整 Q，不阻塞；不 OK 则直接取用已在路上的完整 Q → **省掉回退 RTT**。
- 必须实现并对比：`sync_fallback`（串行，多一次 RTT）vs `pipelined`（并行）。这是时延结论成立与否的分水岭。

## 3. 阈值 θ：分位数初始化 + 慢自适应

### 3.1 离线标定（用独立 held-out 校准集，禁止与测试集重叠）

1. 关闭门控，在 calibration set 上对每一步计算偏差分数 a 和“真值代价” c（见 §4.2）。
2. 统计 a 的分布，取分位数 q ∈ {90%, 95%, 99%} → θ_q。
3. 对每个 θ 扫描，记录：回退率、接受率损失、平均上行字节、每-token 延迟、质量指标（§5）。
4. 选“质量约束下延迟最小”的 θ* 作为论文主工作点；同时报告全曲线（θ–回退率–接受率–延迟）。

### 3.2 线上慢自适应（可选，默认关）

- 长窗口（≥500 token）EMA 监控回退率与接受率损失；
- 仅在越界时按固定步长微调 θ，并限制在离线标定区间内；
- 不逐 token 调，避免震荡。
- 论文主结果用**固定 θ\***（分位数规则），自适应只作为 robustness 补充实验。

### 3.3 报告口径

- 统一报告“分位数规则”（如 95% 分位），而不是某数据集上的魔数 θ；
- 跨数据集/跨模型报告 θ 数值的稳定性（表）。

## 4. 偏差分数与“近似有效”的证明口径

### 4.1 草图偏差分数（门控输入）

推荐主实现（保 TV 上界）：
    a = ‖R·Q − R·P‖_1 / k
备选（内积/重叠）：
    a = 1 − <R·Q, R·P> / (‖R·Q‖·‖R·P‖)
二者都要实现，主文报一个、附录报另一个。

### 4.2 真值代价（仅标定阶段计算，用于验证门控有效性）

- TV(P, Q_full)、KL(P ‖ Q_full)、接受率差 Δα = α_full − α_approx、以及“接受判定翻转率” flip = Pr[ accept(P,Q̃) ≠ accept(P,Q_full) ]。
- 门控的有效性 = a 与 flip/Δα 的相关性（报 Spearman 相关系数 + 分桶命中率/ROC-AUC）。

### 4.3 必须证明的三件事（论文核心证据）

1. **保真性**：a 与真实接受判定翻转率高度相关（AUC ≥ 0.9 为达标线），证明“尺子量得准”。
2. **可控性**：在 θ 分位数规则下，回退率 ≤ 目标预算（如 5%/10%），且回退率、接受率损失随 θ 单调变化。
3. **收益性**：在相同带宽下，Ours 的每-token 延迟低于 B2/B3/B4；并且存在带宽区间使 Ours 优于无损基线 B1（画出交叉点）。

### 4.4 无损性声明的边界（必须诚实写）

- 近似 Q̃ **只进接受判定**；重采样用精确 P → 输出 token 的**支撑集**与 B1 一致，不产生 P 不支持的 token。
- 但由于接受判定改变，输出分布**不严格等于** B1。因此论文措辞为“支撑保持（support-preserving）有损近似”，**不要声称 distribution-preserving / lossless**。损耗用 token 级 KL、生成质量（见 §5）量化。

## 5. 评估指标

### 5.1 主指标

| 类别 | 指标 | 说明 |
|---|---|---|
| 接受 | 平均接受长度 τ、接受率 α、每步推进 token 数 | 与 B1/B2 对比，量化“损失多少接受率” |
| 延迟 | 见 §6 全部分段时延 + 每-token 延迟 | 主结论指标 |
| 通信 | 平均上行字节/步、压缩比、回退率 | 证明省字节 |
| 质量 | 生成任务指标（见下） | 证明“牺牲无损换加速”可接受 |

质量指标按任务：
- 语言建模：困惑度（在 Wikitext-2 / C4）、token 级 KL(P‖Q)、TV(P,Q)；
- 代码：HumanEval pass@1；
- 数学/推理：GSM8K / MATH accuracy；
- 对话/通用：MT-Bench 或 AlpacaEval（可选）；
- 长文本：Needle-in-a-Haystack 或 LongBench（可选）。

### 5.2 消融（ablation）

本期必做（4 项）：

1. 草图门控 on/off —— 证明门控本身的收益，而非低秩 alone；
2. sync_fallback vs pipelined —— 证明隐藏回退 RTT 的实现是必要的；
3. 分位数 θ ∈ {90%, 95%, 99%} —— 回退率/接受率/延迟的 Pareto 曲线；
4. 低秩秩 r ∈ {2,4,8} 与草图维度 k ∈ {64,128,256} —— 两条率失真旋钮曲线。

预留（本期不做，写进 future work 或补充材料）：有/无长尾精确传、回退策略 A vs B、草图 R 稀疏 vs 稠密、热启动 on/off。

### 5.3 敏感性与鲁棒性

- 带宽扫描 {1,5,10,50,100} Mbps；RTT 扫描 {10,30,50} ms；
- 草稿长度 N ∈ {2,4,8}；
- 换 draft 模型（≥2 个不同家族）、换 target 模型（≥2 个）；
- 输入分布漂移：训练域 vs 域外数据，看 θ 稳定性。

## 6. 时延测量（必须逐项记录，缺一项审稿人就会问）

所有时延单位 ms，报 **mean / p50 / p90 / p99**。硬件、batch=1、CUDA graph 开关、warmup 步数都要固定并记录。

| 字段 | 含义 |
|---|---|
| t_draft | 边端 draft 前向（含 LM-head、低秩投影） |
| t_sketch | 边端计算草图 s=R·Q |
| t_serialize | 边端序列化上行 payload |
| t_upload | 上行传输 = payload_bytes / B_up（+ 协议开销） |
| t_queue_edge / t_queue_cloud | 两端排队 |
| t_prepare_cloud | 云端还原 Q̃ = B·c、算 s_P |
| t_gate | 门控判定 a ≤ θ |
| t_verify | 云端 target 前向（验证 P） |
| t_resample | 拒绝后重采样（精确 P） |
| t_accept | 接受/拒绝判定与更新 |
| t_fallback_trigger | 触发回退的事件计数与判定耗时 |
| t_fallback_upload | 回退补传耗时（回退-A）或 token-only 验证（回退-B） |
| t_downlink | 云端→边端确认/token 回传 |
| t_e2e_per_step | 单步端到端 |
| t_e2e_per_token | **主指标**：t_e2e_per_step / 该步推进 token 数 |
| rtt_measured | 实测往返（用于校验配置值） |

额外记录：
- payload_bytes_per_step（分场景：正常步 / 回退步）；
- 每步是否发生回退（bool），便于算回退率与分场景时延；
- GPU/CPU 利用率、显存峰值（可选，用于证明“不靠吃资源换时延”）。

## 9. 验收标准（决定这个优化点能否进论文）

- [ ] 草图开销：t_sketch / t_draft ≤ 0.1%；草图字节 ≤ 完整 logits 的 1%（k=128, N=4, V=32k 时约 1KB vs 256KB）。
- [ ] 门控有效性：a 与接受判定翻转率 AUC ≥ 0.9。
- [ ] 可控性：在选定 θ\* 下，回退率 ≤ 10%，接受率相对 B1 损失 ≤ 5%。
- [ ] 收益性：存在一组真实带宽配置使 Ours 每-token 延迟优于 B2（token-only），并给出与 B1 的交叉点；主图三条线交叉关系清晰。
- [ ] 消融完整：§5.2 本期 4 项全部有数，且草图门控 on/off 显示门控本身有正收益。
- [ ] 质量：任务指标相对 B1 的相对退化在预定预算内（如 pass@1 降幅 ≤ 1pt，PPL 增 ≤ 0.1）。
- [ ] 复现：一条命令复跑，随机种子固定，误差在报告区间内。

若“收益性”一条在目标场景下无法通过：诚实报告门控自动退化为全量传输/token-only，不强行写进主方法；此时该优化点退为 appendix 分析，论文主贡献另找。

## 10. 与相关工作的一句区分（写进 related work，供实现者理解动机）

- SlimSpec / FR-Spec / VocabTrim / SpecVocab：优化**单卡 LM-head FLOPs**，不跨设备、不近似通信。
- Ygg：token-only 无损，不传 Q；接受条件严格精确匹配。
- EdgeSpec：边缘侧分层投机、熵驱动调度，不传 Q、不做草图。
- Ours：**把低秩从“算子”改造成“跨设备通信表示”，草图门控保证可回退的有损边界，零训练、即插即用、支撑保持。**
